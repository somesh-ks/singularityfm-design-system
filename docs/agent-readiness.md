# Agent readiness

How ready this design system is for coding agents, scored on the [Agent-Ready Design rubric](https://agentreadydesign.com/rubric) v0.1 (MIT; [RUBRIC.md](https://github.com/hgillispie/Agent-Ready-Design/blob/f69f88c1d60fac06c2ad657f0a61319d96beaf23/RUBRIC.md) at f69f88c). DS-14 adopted it; the steps that raise the scores are under [The plan](#the-plan). `node scripts/docsCheck.mjs` fails when the summary line or the category table no longer follows from the criteria.

Summary: floor 0, retrieval 2, median 2, tier 0.

- **Floor**: the lowest score in categories 1 to 4, the basics. Below 2, agents drift however good the retrieval is.
- **Retrieval**: the highest score in category 5, how agents find the system.
- **Median**: of all 31 criteria.
- **Tier**: the rubric's informal tiers, from 0 (pre-agentic: agents can read the system but will drift) to 4 (self-healing). Tier 2, agent-legible, needs floor, retrieval and median all at 2.

Supernova's five checks, an outside number, gave 7 of 10 on 2026-11-11; they are rechecked at each release.

Scored on main at 1c967e3 (0.12.0), 2026-11-13.

## How it is scored

- **Strict.** A level counts only when it and every level below it hold across the whole library: every component, token and page. One component that breaks a level's signal puts the criterion one level down. Plans and work in progress count for nothing.
- **Blind.** At the end of each plan step, fresh agents score the repository without seeing earlier scores: one per pair of categories, each followed by an adversarial checker that tries to refute every score in both directions and reruns the counts. The table holds the checked score; a row the checker changed says so under Disagreements.
- **No summed score.** The rubric warns that a 0 to 100 total invites gaming; the floor, the retrieval level and the median are the three numbers it reports.
- **Rescoring.** Run the rubric's [self-assessment prompt](https://github.com/hgillispie/Agent-Ready-Design/blob/main/prompts/self-assessment.md) with the strict rule above in a fresh session, then the checker; replace the table and the summary line; `node scripts/docsCheck.mjs` must pass.

## Learnings

What other systems and studies found, kept short; each figure is its publisher's own and was not reproduced here.

- **CLI before MCP.** Atlassian's design-system CLI beat their own MCP on their benchmark: 8% faster, 8% fewer tokens, and agents picked it 60% more often. Every coding agent we use has a terminal, so `ds` is the retrieval surface (DS-14) and an MCP waits until a host without one needs the system.
- **One source, several outlets.** Atlassian's CLI, MCP and skill read the same generated content. Here `ds`, `system.json`, the part pages, `llms.txt` and the guide all come from one build; a second hand-kept copy (3.1) is the gap to close, not a new outlet.
- **Fewer round trips beat more context.** Atlassian's batched calls halved tool calls. `ds batch` and the "Next:" hint after each search do the same; the 2026-10-30 lookup trial here cut tool calls by 44% and time by 31%.
- **Foundations up front, components on demand.** The rubric's 5.3 and Indeed's report agree: a short always-read rule file plus per-component lookups, never every rule every turn. `foundations.md` stays under 4 KB for that reason (DS-12).
- **Docs that drift are worse than none.** Atlassian's line, and the reason drift checks (8.3) run in CI here.
- **Measure outcomes, not artifacts.** A score says the files exist; only an agent given a task shows whether they help. The Open Design System Bench's method (intent tasks that never name the component, mechanical grading first) is what step 3 copies; small gains need more tasks than the 8 we run, so only large differences count.

## The agent test

A score says the files exist; this says whether they help. `scripts/agentEval/run.mjs` gives a coding agent (Claude Code, and the Antigravity CLI when asked, DS-15) each task in [tasks.json](../scripts/agentEval/tasks.json) (8 intent tasks from the owner's real asks, frozen 2026-11-13, none naming a part) in three setups: the reader app as it is, a new Astro app with the package and the one guide line its AGENTS.md asks for, and the same app without that line. It grades with no model call: the expected part used, imports the package does not export, other UI libraries, `ds validate` errors, `astro check`, and from the transcript the time, tokens, tool calls, whether `ds` ran and whether the guide was opened. `tasks.test.ts` fails when a task names a part or when anything the package gives an agent quotes a task.

Weekly and after each publish, [agent-eval.yml](../.github/workflows/agent-eval.yml) runs both agents on the two new-app setups in GitHub Actions (DS-16). Each signs in with a key made only for this and capped at a monthly spend, from the `agent-eval` environment, which only `main` can use. The environment's `AGY_MODEL` variable picks Antigravity's model. The rows land in the run's summary, and no transcript leaves the runner. A run starts by hand from the Actions tab (agent-eval, Run workflow).

The reader app setup needs the private app, so it runs on the owner's computer at each release, on his own sign-ins. Transcripts stay there; only the summary rows come here. In PowerShell, from a clone of this repository with Node 24 and pnpm:

```powershell
node scripts/agentEval/run.mjs --app C:\path\to\singularityfm-app
node scripts/agentEval/run.mjs --app C:\path\to\singularityfm-app --agents claude,antigravity
```

About 24 runs of 2 to 12 minutes each per agent, unattended. Claude Code runs `claude-haiku-5-5` unless `--model` names another, so every run is on the same model whatever your own default is; `--agy-model` picks Antigravity's. `--setups bare-guide,bare` skips the app; `--user-settings` adds your own Claude settings and plugins, to compare a run with them. The summary prints at the end and is saved beside the transcripts in `scripts/agentEval/runs/`.

The Antigravity runs need `agy` signed in once in a normal session. Both agents read the setup's AGENTS.md, but they are not held to the same tools: Claude Code may edit files and run pnpm, npx, ls and cat, while `agy` has no such list outside its global settings, so it runs with every tool approved, inside its terminal sandbox (workspace and temp folders, no network) where your system has one. For both, a `git push` from the test's copy of the reader goes nowhere. `agy` also loads your global Antigravity rules, and any memory it keeps between conversations, which Claude Code's runs leave out. Compare the two agents on the same setup, and read a gap as the agent plus its defaults, not the model alone. The summary's rows paste straight under the table below.
