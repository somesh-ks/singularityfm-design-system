## DS-16: the weekly agent test runs in GitHub Actions on spend-capped keys; the app setup stays on the owner's computer

- Status: active; amends DS-14 (its "on the owner's computer, no API keys") and DS-15 (Antigravity on his own sign-in)
- Date: 2026-11-14
- Decision: the owner chose to move the weekly agent test to GitHub with a capped key (2026-11-14), and offered a Gemini key for the Antigravity runs. `.github/workflows/agent-eval.yml` runs Claude Code and `agy`, one job each, on the two bare setups every Monday after `release.yml` and after each publish, and on demand. Each agent signs in with a key made only for this, with a monthly spend limit, from the `agent-eval` environment, which only `main` can use; `AGY_MODEL` in that environment picks Antigravity's model, and Claude Code keeps `claude-haiku-5-5`. Only the summary rows reach the job summary.
- Context changed: DS-14 kept keys out because the owner had not been asked. Teams that run agent evals usually run them in CI on a scoped key, on a schedule and at release. A run on a computer only works when that computer is on and signed in. Haiku costs about $1 to $3 per Claude baseline, estimated from the first run's medians.
- The key is contained, not kept from the agent: the agent runs shell commands with its key in its environment, so a hostile page or package could read it. So: a dedicated key with a spend limit, never on a pull request, a checkout with no token, each key in its own agent's steps only, and no transcripts uploaded (GitHub masks secrets in logs, not in artifacts).
- Stays on the owner's computer: the reader app setup, at each release. This repository is public and the app is private, so a run in CI would need a token to the app and could put its code in public logs.
- Rejected: a Windows scheduled task (runs only while his computer is on and signed in); running on every pull request (cost); uploading transcripts as artifacts.
- Revisit if: a key is spent past its limit or leaks, or the app repository gets its own agent-test job.
