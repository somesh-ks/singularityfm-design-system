## DS-7: a stateful component renders whole on the server and hydrates where the page draws it, with client:visible

- Status: active; amends [DS-3](DS-3.md) (of client:visible and client:idle, client:visible) and [DS-5](DS-5.md) (the shim of a component that needs hydration carries the directive)
- Date: 2026-11-09
- Decision: the pilot of the stateful families (Field, Switch, Slider), which the families after it copy.
  - One `.tsx` per component, on its Base UI primitive, renders its whole look on the server: every state it is drawn in is in the HTML (the Switch's `data-checked` and `data-indeterminate`, the Slider's thumb and its `--range-fill`), so nothing moves when it hydrates and a person can read it before.
  - The page opts in, at the call, with Astro's own directive: `<Switch client:visible ... />`. The library cannot set a directive from a `.tsx` (it is an attribute of the call in an Astro page), and a React island needs none: the component hydrates with the island. In an Astro page a component starts from `defaultChecked` or `defaultValue` and keeps its own state, since a page cannot hold React state; in an island it is controlled (`checked` and `onCheckedChange`, `value` and `onValueChange`).
  - The directive is `client:visible`. A person presses what they can see: a control on screen starts loading the moment the page shows it, one below the fold when it scrolls into view, so the island is loading before the finger arrives. `client:idle` waits for an idle main thread, which on a phone still running the page's own scripts comes after the first tap more often.
  - A component that works as a native element unhydrated takes no directive. The Field is Base UI's Field control, a native input or textarea: it types, validates natively and submits before any script. Base UI's own state (`data-dirty`, `data-touched`, a `Field.Root`'s validity and messages) is for a React island's form.
  - The deprecated `.astro` shim of a component that needs hydration carries `client:visible` itself, the one literal its template may hold (`designSystem.test.ts`), and turns `checked` and `value` into `defaultChecked` and `defaultValue`, so an old call keeps a control that answers. The Field's shim carries none.
- Before hydration (DS-4's revisit trigger), measured in Chromium with the scripts held back:
  - Field: nothing is lost.
  - Switch: it draws its state and takes focus; a press (a tap, a click, a click on its label, Space) is lost. A form submitted then posts the server's value: the hidden checkbox carries `name` and `checked`.
  - Slider: it draws its thumb and fill in place; a press or a drag is lost. Tab reaches the hidden range input, whose arrow keys move only that input's value; hydration puts it back, so those keys are lost too, and a form submitted in that window sends the moved value.
  - The window is the island's fetch after the control is on screen: React and its client renderer, 69 kB gzipped, shared by every island and cached across pages, the Switch 2.5 kB, the Slider 9 kB.
- The renderer (DS-3's revisit trigger): `@astrojs/react` ships its client renderer only to a page with an island. In the style guide, the 10 component pages whose controls or preview draw a Switch or Slider carry it and the other 24 pages none; the pack-and-install test fails a page with no Switch or Slider that hydrates, and checks that each island's component and renderer modules were built.
- Consequences: an island sits in an `<astro-island>` element (`display: contents`), so a parent's child combinator (`.settings-row > .slider-input`) no longer reaches a Switch or Slider drawn in an Astro page; a descendant selector does. A page script that sets `checked`, `indeterminate` or `value` on the old input sets the hidden one, which React does not read: it renders the control in a React island and passes the state as props. Reading still works: the Switch's hidden checkbox fires `change` with its `checked`, and its button holds `aria-checked`.
- Why: one rule a family can copy without a choice of its own, a full look before any script, and no script on a page that draws no control that needs one.
- Rejected: `client:load` (every control on a page hydrates at once, off screen too); `client:idle` (above); `client:only` (no server markup: a shift when it draws, and nothing to read before); an Astro wrapper per component that hydrates itself (a second source beside the `.tsx`, the twin DS-3 rejects, and an island cannot draw it); a native checkbox as the Switch's root, so a tap works unhydrated (DS-4 names the button, and the checkbox's own state and React's would drift); hydrating the Field (a native input already does what it must before a script).
- Revisit if: the app's browser suites show a tap before hydration lost on a phone (DS-4); or a custom Astro directive that hydrates on the first press and replays it is worth an integration every consumer registers.
