## DS-18: The weekly agent test runs one setup; a change counts only past chance

- Status: active; amends DS-14 (weekly and at release, every setup) and DS-16 (both new-app setups weekly)
- Date: 2026-11-14
- Decision: the owner asked whether all three setups need to run (2026-11-14) and chose, on a card: weekly, CI runs only the new app with the guide line, the setup a docs change moves; after each publish and when started by hand, it also runs the app without the line; the reader app setup stays on his computer at each release. A component added after the task freeze (`components_at_freeze` in tasks.json) needs a task that expects it, or `tasks.test.ts` fails. `compare.mjs` reads two or three summaries and counts a change only on the tasks every run has, and only when two or more tasks move the same way, or one does and the run before moved the same way; otherwise it is noise. Grading stays mechanical: on a card he chose no model judge (Jev) yet.
- Why: with 8 tasks an agent flips one by chance, so a one-task move says nothing about the docs. The setup without the guide line changes only with the package, not with the docs, so weekly it repeats the last result at the cost of half the run.
- Rejected: a larger task list first (more cost per run before the baseline says which tasks are noisy); a model judge now (it costs every run and needs its own calibration before its scores mean anything).
- Revisit if: the weekly rows stay flat for a month while the docs change, or a judge is needed to tell two pages that both use the right part.
