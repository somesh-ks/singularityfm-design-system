## DS-10: no pixel length in a stylesheet; a width comes from the content or a token

- Status: active
- Date: 2026-11-10
- Decision: the owner's rule ("avoid pixel values as hardcoded thing, as a rule; find another way"). A stylesheet writes a length as a token, rem, em, ch, lh, a percentage or a calc() of those, never in px. Zero (`0px`, which a calc() or a registered property needs) and the 1px hairline pass. The geometry of an SVG scene (the Avatar's pivot) is named in `PX_EXCEPTIONS` with its reason; a caller names its own the same way. A media query reads rem.
  - A width that must hold across states is reserved from the content (DS-9: every word stacked in one grid cell, the widest sets the width), never measured and written down.
  - `raw-px` is a rule of the shipped `validate` (`ds validate`), and `rules.test.ts` runs it over every stylesheet of the library, so one pasted in fails the gate.
- Why: a measured width (the hero Play chip at 141.5px) is right for one set of words, one text size and one mood; the next label, a larger text setting or the expressive mood makes it wrong, and nothing says so.
- Rejected: a ratchet baseline for the library (it holds no raw px today, so it can start at none); also checking markup and inline `style` props (not done: closed when a page draws a px length there).
- Revisit if: a component needs a length no token, rem, em or ch expresses.
