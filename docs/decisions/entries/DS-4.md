## DS-4: every control with state is built on Base UI; links and static parts are not

- Status: active; amends [DS-3](DS-3.md)
- Date: 2026-11-08
- Decision: the owner's call, reviewing the design system master plan. A component with state or keyboard behaviour is built on its Base UI primitive, Button and Field included, so the library has one API shape (`render`, `data-*` state attributes) for every control: Button, IconButton and Fab on Button; Field; Switch; Slider; Avatar; Chip; the segmented controls (the one that navigates between views on Tabs, the one that picks a value on Radio); Dialog; Sheet; Menu; Select; Code's copy button. A link is never a Base UI primitive: SectionTabs are links to the sections of one page, so ARIA tabs (arrow keys, "tab 2 of 4", hidden panels) would announce the wrong thing. A part with no behaviour (Icon, BrandMark, Flag, Badge, Banner, ChapterAside, RowExit, Ripple) is plain React and ships no script.
- Releases: a migration that changes markup (Switch becomes `<button role="switch">`, CSS moves from `input:checked` to `[data-checked]`) is breaking by [COMPATIBILITY.md](../../../packages/design-system/COMPATIBILITY.md), and so is making `@base-ui/react` a required peer. These go on a Changesets pre-release line (`1.0.0-next.N`) the app can try, entered only after the non-breaking families have shipped as minors (pre mode makes every release a prerelease). 1.0.0 keeps the deprecated `.astro` paths as aliases; a later major removes them once the deprecation window has passed.
- Why: DS-3 kept Base UI off a control a native element serves. For practice in an industry-shaped system (the shadcn shape puts one primitive under every stateful input) the uniform API is worth the hydration, and a native element no longer decides it.
- Rejected: Base UI on every part, links included (wrong semantics for SectionTabs); Base UI only on overlays, as DS-3 had it (two API shapes across the library's inputs).
- Revisit if: the app's browser suites show slower interaction on a page that draws many controls, or a tap before hydration is lost on a phone.
