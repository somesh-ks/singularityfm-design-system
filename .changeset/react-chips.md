Chip, ChipGroup, PlayChip, SegmentedChoice, SegmentedNav and SearchField are React components (D237, D243): import them as `@singularityfm/design-system/Chip`, `/ChipGroup`, `/PlayChip`, `/SegmentedChoice`, `/SegmentedNav` and `/SearchField`. Each draws the markup and classes the app types by hand today, so a page can switch with no visual change. Chip, ChipGroup, SegmentedChoice and SearchField are native inputs, PlayChip a native button and SegmentedNav the app's `role="tablist"` of buttons, all React-rendered with no client directive (DS-8), and a page's script reads and sets them as it does now. Start them with `defaultChecked` or `defaultValue` in an Astro page, and control the inputs in a React island. SegmentedNav ships no script: its behaviour (a press, Left, Right, Home and End, `data-param`) moved unchanged from the app's `segmentedNav.ts` to `@singularityfm/design-system/segmentedNav`, so the page calls `mountSegmentedNav(list, onSelect)` once for each list, and `selectTab(list, value)` for a view read from the address, as it does now; only the import path changes. The page draws the panels and names each with a tab's `controls`. Chip and SearchField take `className` on the pill and every other attribute on the input; SearchField requires `label`, its input's name for a screen reader. The registry now lists `filter-chip`, `filter-chips`, `filter-chips-scroll`, the play chip's `chip` classes, `segmented-choice`, `segmented-choice-item`, `segmented-nav`, `segmented-nav-tab`, `segmented-nav-compact` and `search-field`, so the app's `systemUse.test.ts` fails a page that still types them, from the bump that takes this release. No existing class, rule or markup changes.
