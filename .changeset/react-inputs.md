BREAKING: Field, Switch and Slider are React components on Base UI (DS-4, DS-7), and `@base-ui/react` (^1.9.0) is now a required peer: install it. Import them as `@singularityfm/design-system/Field`, `/Switch` and `/Slider` and pass `className`. In an Astro page draw the Switch and the Slider with `client:load` and start them from `defaultChecked` and `defaultValue`; in a React island pass `checked` with `onCheckedChange` and `value` with `onValueChange`. The Field needs no directive. Their `.astro` paths are deprecated shims that keep `class`, every attribute, and `checked` or `value` as the starting state, the Switch and the Slider hydrated where they are drawn; `ds validate` warns on them. What a page, a stylesheet or a script changes:

- Switch markup. Before: `<input type="checkbox" role="switch" class="switch-input">`. After: `<button type="button" role="switch" class="switch-input" aria-checked data-checked|data-unchecked>` and a hidden checkbox beside it that carries `name` and the value. `id` names the button, so `<label for>` still names and presses it.
- Switch CSS. Before: `.switch-input:checked`, `.switch-input:indeterminate`. After: `.switch-input[data-checked]`, `.switch-input[data-indeterminate]`. `:disabled`, `:enabled`, `:active` and `::before` still match the button, a disabled fieldset included.
- Switch scripts. Before: a script set `input.checked` or `input.indeterminate`. After: render the Switch in a React island and pass `checked` and `indeterminate` (a new prop: mixed until the next press). Reading works as before: the hidden checkbox fires `change` with its `checked`, and the button holds `aria-checked`. A `[data-*]` you pass lands on the button, not on an input.
- Slider markup. Before: `<input type="range" class="slider-input">`, wrapped in `.slider-hue-field` or `.slider-wave-field` for `hue` and `wavy`. After: `<span class="slider-input" role="group">` (wrapped the same way) holding Base UI's control, track and thumb as spans, the thumb holding a hidden `<input type="range">` with `name`, `min`, `max`, `step` and the value. Where nothing sizes it, it is 129px wide, as the native range was.
- Slider CSS. Before: `.slider-input::-webkit-slider-thumb` and `::-moz-range-thumb`, `::-moz-range-progress`, `.slider-input:disabled` and `:enabled`. After: `.slider-input [data-index]` (the thumb), `.slider-input[data-disabled]` and `:not([data-disabled])`.
- Slider scripts. Before: the caller kept `--range-fill` on the input or its field and set `input.value`. After: the Slider keeps `--range-fill` from its own value (drop that script), and a React island passes `value`. `id` is the root's: name it with `aria-label` or `aria-labelledby`, since a `<label for>` cannot reach the hidden input. A wavy Slider in Default, and one whose caller never set `--range-fill`, now draw their fill.
- Astro pages. A Switch or Slider drawn with `client:load` sits in an `<astro-island>` (`display: contents`): a parent's child combinator (`.settings-row > .slider-input`) no longer reaches it; use a descendant selector.
- Deprecated: `switchClass()`, `sliderClass()` and `sliderWaveFieldClass()`. A native checkbox or range with these classes no longer draws a switch or a slider; draw `<Switch>` or `<Slider wavy>`. `fieldClass()` is unchanged.
- Field: the same native input or textarea, with an `id` when none is given. Its shim takes `value` as the starting value.
