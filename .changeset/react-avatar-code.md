BREAKING: Avatar is a React component on Base UI and Code a React component (DS-4, DS-7, DS-8). Import them as `@singularityfm/design-system/Avatar` and `/Code` and pass `className`. Their `.astro` paths are deprecated shims that keep `class` and every prop; `ds validate` warns on them. What a page, a stylesheet or a script changes:

- Avatar, a shape. Before and after: the same `<span class="avatar">` (a `<button>` with `label`) holding the same SVG, rendered on the server with no script. Draw it with no client directive, as before: a script that redraws it in place (`innerHTML = avatarMarkup(id)`, `data-play`, `data-state`, `data-face`, `data-tone`) keeps working, and a slot's child combinator still reaches it. `avatarMarkup()`, `avatarClass()` and the other exports of `avatar.ts` are unchanged; `avatarArt(id, clip)` is new, the SVG's contents.
- Avatar, a photo. Before: the photo stayed, broken, when it failed to load. After: drawn with `client:load` in an Astro page (or in a React island), the shape stands in once it hydrates, even for a load that failed before. The photo's `<img>` carries `aria-hidden="true"` (its `alt` was already empty) and React may write a `<link rel="preload">` for it. The shim draws no island, so a photo it draws stays as before.
- Code. Before: `<Code>` was an Astro component whose inline script copied through `wireCodeCopy()`. After: draw `<Code client:load ...>` in an Astro page; a React island draws it as it is. The shim carries `client:load`. It renders whole on the server; a press before hydration is lost. It sits in an `<astro-island>` (`display: contents`): a parent's child combinator no longer reaches `.code-snippet`; use a descendant selector.
- Code markup. The root drops `data-code` and `data-copied-word`, the button `data-code-copy` and the status `data-code-said`: a script that found the snippet by them finds the classes instead. The button is the Icon button (`.icon-btn.press.code-snippet-copy`) and presses like one. The root still takes `data-copied` while it shows its check, and `.code-snippet-text` is the text it copies, read when pressed, so a script that rewrites it copies its own.
- `codeSnippetHtml()` and `wireCodeCopy()` keep working for a snippet a script builds from a string; its button gains `.press` too. `copySnippetText()` and `COPIED_MS` are new exports of `code.ts`, the copy both share.
